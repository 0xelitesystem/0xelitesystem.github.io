# 0xelitesystem.github.io

The searchable index for every open-source repo I publish: 335 in total, 178 single-file browser tools with live demos and 157 plain-language references.

## Live site

https://0xelitesystem.github.io/

## Use

1. Open https://0xelitesystem.github.io/.
2. Type in the search box (press `/` to jump to it). Every word must match the repo name or description; name matches rank first.
3. Narrow the list with the All, Tools or References chips.
4. Click a repo name to open it on GitHub, or "live demo" to open a tool's page.

## Why this exists

GitHub's profile page is not a usable index for hundreds of small repos. This is one static page that lists every repo with a one-line description and a link to its live demo, with no tracking and no build step for the page itself. MIT licensed.

## What is here

- `index.html` one page, no build step, no dependencies. It fetches `catalog.json` and filters in the browser.
- `catalog.json` the machine-readable catalog: one entry per repo with slug (`s`), type (`t`, tool or ref), and description (`d`).
- `llms.txt` a plain-language summary for AI crawlers, following the llms.txt convention.
- `sitemap.xml` the index plus every live tool demo.
- `feed.xml` RSS of the 40 most recently created repos.
- `.github/workflows/update-catalog.yml` rebuilds all of the above from the live GitHub API every Monday, and keeps the counts in this page in sync.

## How the catalog stays honest

The workflow reads the live repo list, drops forks and archived repos, and refuses to write a catalog with fewer than 100 entries so a bad API response cannot wipe the index. Existing tool/reference classifications win over the automatic guess, so manual corrections survive a rebuild.

## Privacy

The page makes one network request: when it loads, it fetches `catalog.json` from this same site. Your search terms and filter choice stay in the page. Nothing is sent anywhere, nothing is saved to localStorage or cookies, and there are no analytics or third-party scripts. Links to github.com and to tool demos are only followed when you click them.

## Run locally

```
git clone https://github.com/0xelitesystem/0xelitesystem.github.io
cd 0xelitesystem.github.io
python -m http.server 8000
```

Then visit http://localhost:8000/. Serve it rather than opening `index.html` directly, because browsers block `fetch` of `catalog.json` from a `file://` page.

## Build

No build step for the page: `index.html` is one file. `catalog.json`, `llms.txt`, `sitemap.xml` and `feed.xml` are regenerated by `.github/workflows/update-catalog.yml`, described above.
